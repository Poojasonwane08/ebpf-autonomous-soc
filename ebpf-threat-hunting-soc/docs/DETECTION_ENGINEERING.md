# Detection engineering

Four detection layers run on every normalised kernel event.

## 1. Kernel event → MITRE ATT&CK translation (`config/mitre_mapping.yml`)

Declarative rules that tag *telemetry* with techniques (they do not raise alerts on their own; they
enrich events, process trees and alerts):

```yaml
- id: creds-to-root
  technique: T1068
  match:
    type: {equals: privilege_change}
    new_uid: {equals: 0}
    uid: {ne: 0}
```
Operators: `equals, ne, in, startswith, endswith, contains, regex, gt, lt`.
21 techniques across 12 tactics are defined; add a technique to `techniques:` and a rule to `rules:`.

## 2. Sigma rules (`rules/sigma/*.yml`)

Standard Sigma YAML evaluated by `soc/sigma.py`. Sigma field names are mapped to the normalised schema:

| Sigma field | Event key | Sigma field | Event key |
|---|---|---|---|
| Image | binary | DestinationIp | dst_ip |
| CommandLine | cmdline | DestinationPort | dst_port |
| ParentImage | parent_binary | DestinationIsExternal | dst_external |
| User | uid | TargetFilename | file_path |
| NewUid | new_uid | PtraceRequest | ptrace_request |
| Hostname | host | EventType | type |

`logsource.category` selects event types: `process_creation`, `network_connection`, `file_access`,
`privilege_change`, `process_access` (ptrace), `memfd`. Without a category the rule sees every event.

| Rule | Level | ATT&CK |
|---|---|---|
| Web server process spawns a shell | high | T1505.003, T1190 |
| Linux system discovery commands | low | T1033, T1082, T1087.001 |
| Access to /etc/shadow | high | T1003.008 |
| SSH private key read by non-SSH process | high | T1552.004 |
| Payload download to temp / pipe-to-shell | high | T1105 |
| Fileless execution from memfd / /proc/self/fd / /dev/shm | critical | T1620 |
| memfd_create from scripting/download process | high | T1620 |
| Ptrace process injection | critical | T1055.008 |
| Unexpected privilege escalation to root (commit_creds) | critical | T1068 |
| Outbound SSH from a non-admin server | high | T1021.004 |
| Reverse shell command line | critical | T1059.004 |
| Cron persistence | medium | T1053.003 |
| Exfiltration via HTTP upload tools | high | T1048 |
| Cryptominer / mining pool connection | high | T1496, T1571 |
| Log or history tampering | high | T1070.002 |

Supported: maps (AND), lists (OR), modifiers `contains startswith endswith re all gt lt`, wildcards,
conditions with `and / or / not / ( )`, `1 of x*`, `all of x*`, `1 of them`.

**Adding a rule:** drop a new `.yml` in `rules/sigma/`, restart, and add a test in `tests/test_sigma.py`.

## 3. Behavioural sequence detectors (`soc/anomaly.py: BehaviourDetector`)

Stateful detectors that look at *sequences* rather than single events:

| ID | Sequence | Severity |
|---|---|---|
| BHV-FILELESS | `memfd_create()` by pid P, then within 60 s an exec from `/proc/*/fd/*`, `memfd:` or `/dev/shm` by P or its child | critical |
| BHV-INJECT | `ptrace(ATTACH/SEIZE)` on pid T then `ptrace(POKETEXT/POKEDATA/SETREGS)` on the same T | critical |
| BHV-PRIVESC | uid ≠ 0 → euid 0 via `commit_creds`/`setuid` where the process lineage has no sudo/su/login/sshd/cron | critical |

## 4. Anomaly model (`soc/anomaly.py: AnomalyModel`)

IsolationForest over process-execution features:

| Feature | Meaning |
|---|---|
| pair_rarity | −log frequency of (parent binary, child binary) in the baseline |
| binary_rarity | −log frequency of the binary |
| writable_binary | binary runs from /tmp, /dev/shm, /proc/*/fd, memfd |
| writable_args | arguments reference those locations |
| uid_class | root / service account / human |
| args_len, args_entropy | length and Shannon entropy of the arguments |
| depth | depth in the process tree |
| spawn_burst | children spawned by the same parent in the last 30 s |

- **Simulated mode:** trained at start-up on ~5 000 benign executions generated by the simulator.
- **Live mode:** learns online from the first 2 000 real executions, then starts scoring.
- **Threshold:** auto-calibrated to the 5 % quantile of training scores, and an alert additionally requires a
  never-seen parent/child pair *and* a novel binary or writable path — this keeps the false-positive rate at
  zero on 10 000 held-out benign executions (`tests/test_cep.py::test_benign_baseline_produces_no_high_alerts`)
  while flagging the attack steps.

## 5. Correlation

`CORR-LATERAL-SSH` (critical, T1021.004): SSH connect on host A + `sshd → shell` on host B within 20 s,
where A's process is part of an incident or A is not an admin host. See ARCHITECTURE.md.

## Threat-hunting workflow

1. Hunt in the **live telemetry** panel or the **process trees** of an incident.
2. Turn a finding into a Sigma rule in `rules/sigma/`.
3. Replay the scenarios with `python -m soc.report` to measure the rule (hits, false positives).
4. If a rule should trigger response, reference its technique in a playbook trigger.
